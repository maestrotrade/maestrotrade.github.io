02 • One-Time Computer Setup

Install Python and the required packages.

1

Install Python 3

Install a current Python 3 release for Windows. During installation, enable the option to add Python to PATH if offered.

2

Open Command Prompt

Press the Windows key, type cmd, and open Command Prompt.

3

Confirm Python works

python --version

You should see a Python 3 version instead of an error.

4

Install the libraries used by both bots

python -m pip install ccxt pandas numpy python-dotenv

CCXT connects the Python code to NDAX; pandas and NumPy support candle/indicator calculations; python-dotenv loads the shared .env file.

03 • Folder Setup

Create one bot folder.

Create this folder in Windows:

C:\NDAX_BOT

Copy the three package files into it. Your folder should initially look like:

C:\NDAX_BOT\ .env crypto_m1_trading_bot.py crypto_m5_trading_bot.py
Important: Windows may hide known file extensions. Make sure the scripts really end in .py and that the configuration is named exactly .env, not .env.txt.
04 • Shared Configuration

Set up the .env file.

Both bots read the same .env, so you configure the account and shared controls once.

NDAX credentials

Open .env in Notepad and enter your own NDAX API credentials in these fields:

NDAX_API_KEY=YOUR_API_KEY NDAX_API_SECRET=YOUR_API_SECRET NDAX_USER_ID=YOUR_USER_ID NDAX_ACCOUNT_ID=

The scripts can discover the account ID, so the Account ID field can normally remain blank. Keep the .env private. Never publish it to GitHub or send your filled-in copy to another person.

Pairs being scanned

NDAX_SYMBOLS=BTC/CAD,ETH/CAD,SOL/CAD,LINK/CAD

This supplied configuration makes both bots scan those four CAD markets. Only add symbols that actually exist on NDAX and that you intentionally want the bots to evaluate.

FIRST RUN — safe test setting

LIVE_TRADING=false LIVE_ARM=

With this setting, the strategy can operate in paper mode rather than intentionally sending real orders. Do this first even if you ultimately plan to trade live.

  • The bot prints its version and mode.
  • NDAX markets load.
  • Your configured symbols show AVAILABLE.

08 • Shared Safety Design

How the two bots cooperate.

SignalSetup qualifies
Shared LockChecks no other bot owns position
EntryMarket BUY in live mode
ProtectionNative stop-market SELL attempted
ExitStop or local TP
The shared lock is designed to allow only one open position across M1 + M5 combined. If one bot owns the lock, the other bot is blocked from opening another position.

These supplied bots are spot-long only: no shorts and no leverage. After a live buy fills, the code attempts to place an exchange-native protective stop-market sell. If that protective stop cannot be created, the code attempts an emergency market sell. The take-profit is monitored locally by the running Python bot, while the native downside stop remains on the exchange.

09 • Live Trading

Only arm live mode intentionally.

Do not change this until paper testing and API authentication are verified. Live mode sends real orders and can lose real money.

Stop both bots with Ctrl+C. Edit .env and change the two shared lines to:

LIVE_TRADING=true LIVE_ARM=YES_REAL_ORDERS

Both conditions must match exactly before the code permits real orders. Restart both bots and confirm the startup says LIVE-ARMED and that private API authentication succeeds. If LIVE_TRADING is true but LIVE_ARM is wrong, the bot's safety check blocks real orders.

Do not distribute a customer package with your own filled-in API credentials. The customer must enter their own credentials locally.

12 • Stop & Restart

How to shut the bots down safely.

To stop a bot, click its Command Prompt window and press:

Ctrl + C

The scripts catch the keyboard interrupt and log that the bot was stopped by the user. To restart, return to C:\NDAX_BOT and run the same Python command again.

Critical live-mode note: the downside stop is designed to rest on NDAX, but the take-profit is managed locally by the Python program. Therefore, do not assume that closing the bot leaves the complete strategy managed automatically. Before shutting down a live bot with an open position, inspect the live NDAX position/order status and understand what protective order remains active.

The state JSON files support restart recovery, and the shared-lock reconciliation is designed not to automatically clear a lock belonging to the other bot.

13 • Troubleshooting

Beginner questions.

'python' is not recognized.

Python is either not installed or not available on your Windows PATH. Install Python 3 and make sure the PATH option is enabled, then reopen Command Prompt.

It says ModuleNotFoundError.

Install the required packages with python -m pip install ccxt pandas numpy python-dotenv.

The bot starts but says authentication failed.

Recheck NDAX_API_KEY, NDAX_API_SECRET and NDAX_USER_ID in .env. Do not add quotation marks or extra spaces unless specifically required. Live mode aborts when private authentication fails.

Why is the bot not trading?

It may simply have no valid setup. Spread, ADX, RSI, EMA separation, volatility, candle size, M5 trend confirmation, cooldown, daily limits, reserve requirements or the shared lock can all prevent an entry.

Can I run M1 and M5 at the same time?

Yes. That is the intended shared configuration: run each script in its own Command Prompt window while both read the same .env and coordinate through the shared position lock.

Can I close the Command Prompt windows?

Not if you expect the local bots to continue scanning and managing their local take-profit logic. Closing the window stops that Python process.

Do these bots short crypto?

No. The supplied code is spot-long only, with no short selling and no leverage.
